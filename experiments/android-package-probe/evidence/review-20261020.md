## 审查意见与处理

| 编号 | 处理 |
| --- | --- |
| P1 429/503 与测试预期不一致 | `AnalysisTransport.exchange` 显式把 429/503 映射为 `SERVER_BUSY`。默认客户端仍由拦截器先拒绝以避免 503 follow-up；新回归移除了注入客户端的网络拦截器，证明映射不依赖该默认实现。 |
| P2 未确认上传可能再次 POST | 说明并测试服务端真实约束：`uploaded` 在同一数据库事务内原子提交，同一草稿第二次 package-set 返回 409。客户端对该 409 只做只读 GET 对账，读到匹配回执才返回 `SERVER_CONFIRMED`，否则原样报告冲突。新增回归验证“GET 未确认 → POST 409 → GET 确认”只产生一个 package-set 请求。 |
| P2 删除回执缺少目标身份 | 现有 v1 DELETE 回执只有 `deleted`/`cleanup_pending`；身份由同源认证连接、精确草稿路径和绑定实例 UUID 的能力令牌共同确定，该信任边界写入 `UPLOAD.md`。兼容服务若额外返回 `id`/`draft_id`，必须匹配当前草稿，否则拒绝回执并保留本机访问材料；新增回归覆盖。 |
