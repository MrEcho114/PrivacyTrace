# 上架准备草稿与缺口

状态为 DRAFT / NOT_SUBMITTED。以下是待最终客户端与运行时证明的材料映射，不是已核实的权限清单、Data safety 答案、法律结论或审核通过证明。技术验收、准入材料、平台审核和公开分发分别记录。

## 权限与包可见性用途

目标用户流程是主动选择一个已安装 App、确认上传其 base/splits，获取静态证据与政策声明对照。生产客户端最终 Manifest 尚未合入本轮基线；下面描述核查方法和拟用理由，不预填“已声明”或“已获批准”。

| 能力／权限 | 拟用理由与最小范围 | 尚需证明 |
| --- | --- | --- |
| 包可见性 `<queries>` | 仅在本机提供用户选择所需的可见应用；整机清单不发送服务端 | 最终 Manifest、可见性实现及用户选择/确认网络观察；更窄范围是否满足功能 |
| `QUERY_ALL_PACKAGES` | 只有最终实现确需广泛可见性时才评估，不因“隐私分析工具”自行认定有资格 | 必要性、替代方案、正式声明和平台审核结果；未获结论时保持 UNKNOWN |
| `INTERNET` | 向选定实例传输已确认材料；可选手机直连用户配置的模型端点 | 最终 Manifest、目标实例隔离、TLS/网络行为、上传内容最小化与披露 |
| 存储/全文件访问 | 不以读取所选已安装包为由默认申请广泛存储权限 | 最终 API 与 Manifest 实际需要；若出现广泛权限先审查替代路径及平台条件 |
| 安装/无障碍/后台能力 | 当前目标不自动证明需要安装他人 APK、无障碍或任意后台能力 | 最终依赖与合并 Manifest 逐项核对；不能将 PoC 的权限状态复制到生产包 |

Google Play 对广泛包可见性有适用范围与声明要求；需据实际核心功能判断，不能将技术可读性当成准入许可。[官方包可见性政策](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en)（2026-10-19 查阅）。

## 数据流与披露草稿

下表来自 #73 的产品约束，是设计声明；每行仍需由同版本实际行为核对。无登录不等于无敏感数据处理，也不能据此直接填写“不收集任何数据”。Data safety 还需覆盖最终客户端 SDK/WebView 的真实行为。[官方 Data safety 指引](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)（2026-10-19 查阅）。

| 数据／路径 | 预定处理与保留 | 需要的证据／当前缺口 |
| --- | --- | --- |
| 已选择的包名、版本、base/splits | 用户确认后发往所选分析实例，不发送整机应用清单 | H01–H12 实际出站、服务端材料索引及哈希；未验证 |
| 政策地址/文本、辅助候选 | 原来源和审计保留，同一校验路径接入任务 | 自动/网页辅助/API 补入的来源与原句记录；不可将模型推断伪装成政策事实；未验证 |
| 代码静态线索、报告及任务事件 | 私有卷与持久索引受任务访问材料保护 | 跨任务/实例拒绝、读取与删除行为、实际存储/日志边界；未验证 |
| 个人模型凭据及模型请求 | 凭据留手机，仅直连用户指定模型服务，切换地址不转发旧 Key；只提供所选 App 信息及用户主动给出的材料，不发 APK、整机清单或任务访问材料 | N11 的可观察传输面、分析入口无凭据及最终 SDK 行为；未验证 |
| 任务访问材料 | 客户端按实例与任务隔离，服务端存验证摘要；不进 URL/公开日志 | 实际存储、日志、切换/恢复与旧材料拒绝；未验证 |
| 保留和删除 | 材料按用户删除，受容量约束；删除记录需在备份恢复后防止复活 | F05/F06/F09、真实保留配置及用户可见说明；未验证，不填任意天数 |
| 诊断及第三方依赖 | 依据实际客户端/代理/SDK 行为列项，不根据计划推断不存在遥测 | 最终依赖清单、SDK 数据说明、应用/代理日志与网络验证；未盘点完成 |
