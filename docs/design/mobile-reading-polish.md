# 移动报告与材料上下文：阅读设计增量

来源：用户明确要求使用 frontend-design 直接设计部分组件/页面并发布PR；对应 #141 的阶段审阅 R3/R4/R5。前置 #160，实施起点 `a4f866c9d43e7c559a3ea92797e36b715ba49303`。R1/R2 仍由前置整合入口处理，本增量不修改其状态/请求逻辑。

## 设计计划

复用 Pioneer：画布 `#F6F5F1`、表面 `#FDFCFA`、正文 `#2C3547`、辅助 `#64696F`、操作 `#333C50`、薄荷 `#DCE9DF`。Noto Serif SC 只用于应用名/页面标题，Noto Sans SC 承载操作与正文，已有等宽字体只用于展开后的包名/标识。复用现有 token，不引入字体、颜色、依赖或动效系统。

报告首先回答“看的是哪个应用、这份结果来自哪里、有什么可查看的依据”。全内容左对齐；应用身份只出现一次，来源与投递仍为两个独立维度。将独立卡片式统计改为摘要内的紧凑数据行；不把统计当作风险/安全评分。来源说明和完整时间留在用户展开的详情内，证据不足/待复核等结论标签继续随对照项可见。

```text
对照报告                            设置
导入    候选    进度    报告
┌ 应用名 / 版本                     ┐
│ 来源类型            本次生成/存档 │
│ 静态证据与政策声明；不证明实际采集 │
│ 数据类型 n · 政策 n · 证据 n     │
│ 报告详情                       ⌄ │
└──────────────────────────────────┘
隐私声明对照
数据类型      当前结论 / 待复核
政策来源                  查看证据
```

候选/进度共用一个材料上下文组件。材料名和版本组成可展开入口，与“更换”在同一行；详情打开后才展示完整名称、来源与材料标识。整行命中区保留48px，不以缩小字号或触控区换取空间。

```text
┌ 材料名 / 版本       详情 ⌄  更换 ┐
│ [用户展开后：完整名称/服务/标识] │
└──────────────────────────────────┘
```

设置继续复用现有 Reka 全屏 sheet 与字段，不改变三部分结构。材料存储位置写“当前分析服务”，显示实际实例；个人模型 Key 的设备本地保存说明保持。

## 计划复核

初稿若继续保留材料卡、应用卡和三个统计卡，只是把现有拥挤层级重新排一次。因此改为单个应用摘要加一行统计，明确让证据对照成为页面主体。保留 Pioneer 指定的暖白和衬线身份；不采用新的英雄区、渐变、装饰插画或卡片动画。桌面仍使用原报告结构。

## 验证边界

先看390px报告/候选代表图，再扩展320/768、200%字号、桌面1440、完整详情、键盘和减少动效检查。浏览器使用固定报告与模拟原生桥，仅证明实际Vue界面行为；真实Android/IME/读屏仍独立列为未运行。验证结果和实际截图在交付时追加。
