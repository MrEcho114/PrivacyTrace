`App.vue` 的移动/抽取 hunk（供 Lead 串行合并识别）：

1. 新增 `mobile?: boolean` prop、`evidenceOpen`/`evidenceClose` emits、`mobile` computed；引入 `EvidencePanel`、`UiSheet`、`UiIcon`。
2. `selectIssue(issue, event?)` 记录触发元素与 `scrollY`，移动端只 emit 开 sheet；`closeEvidence(restoreFocus)` 关闭后返回触发按钮与精确滚动位置；`defineExpose({ evidenceOpen, closeEvidence })` 供外壳消费硬件返回。
3. 移除已迁入 `EvidencePanel.vue` 的 `selectedEvidence`、候选分页（`candidatePage/candidateClaims/candidatePageCount/relatedCandidates`）、`documentFor`、`sentenceContext`；保留 provenance 重置、`openPolicy`（新增政策块焦点落点）与 `jumpToPolicy`。
4. 模板：`topbar`/`intro` 增加 `v-if="!mobile"`；桌面表格包 `v-if="!mobile"`，移动端新增 `.m-issue-list` 整行按钮列表；内联证据区替换为桌面 `EvidencePanel` + 移动 `UiSheet`（内部同一 `EvidencePanel`，`heading=false`）。
5. B 的桌面结构（sample-card/metrics 前置、coverage/SDK/provenance 后置）原样保留；`hierarchy.css`、`MaterialContext.vue`、`pages/*` 桌面改动均来自 B，未回改。

设计差异/说明（未写成已完成的能力）：

- A 的 `UiSheet` 在整合后替换了临时 `UiDialog` seam；本分支没有私有 sheet 副本。sheet 关闭控件为 A 的 48px `.ui-sheet-close`（`aria-label=关闭`），证据面板本身 DOM 单源于 `EvidencePanel.vue`。
- E #146 的动效 token 与 `UiSheet` 进场动画已合入；移动截图的 `animations: disabled` 只冻结截图瞬间的动画，reduced-motion 由 round-2 与 E 的脚本分别断言。C 的 `mobile.css` 只保留 120ms 按压/150ms chevron 过渡，没有 `transition: all`。
- 移动报告来自 `flow.report` 的 `snapshot` 路径，没有桌面报告来源切换器；进度步骤的「刷新进度」仍是报告刷新的入口，未新增功能。合同 §4.3「来源切换/刷新迁移」在此路径下无对象可迁移。
- 材料上下文沿用 C 的轻量 `.m-context`（应用名、材料版本、origin 可展开）。B 的 `MaterialContext.vue` 绑定桌面 workflow 的 `state/context`，移动端 flow 的数据是 native `Upload+LivDraft`，直接复用需要新增 props/行为；因此未复用并在此记录原因。
- 滚动采用 body 滚动 + sticky 顶栏 / fixed 底栏：保留 Tauri WebView 原生滚动恢复与 `App.vue` 证据焦点契约。底部操作栏实际高度用 `ResizeObserver` 发布为 `--m-actionbar-actual`，200% 字号下内容不会被底栏遮住。
- **没有缺失 token**：§3 的全部 `--m-*` 已由 A 的 `theme.css` 提供，`mobile.css` 直接消费，无本地 fallback；只有外壳自有的 `--m-actionbar-actual`（测量值）定义在 `mobile.css` 消费侧。
