2026-10-22用户显式调用ui-ux-pro-max，指定修正导航重复、空间分配失衡、证据关联不直观、状态表达模糊、操作入口分散和按键位置不明确。此文补充[#165](https://github.com/MrEcho114/PrivacyTrace/issues/165)，与[已采纳#167](copy-contract-167.md)共同约束后续接入。保留白色工作面、米白顶栏、四色重点条、单红主操作及Pioneer字系与显著字号。

## 阅读任务与页面结构

读者先识别报告对象和材料范围，再看数据类型及对照结论，选择一条后核对定位与原句，最后阅读政策全文或来源技术信息。不能为了装饰把同一步骤、状态或操作重复铺在多处。

桌面：品牌栏 → 单一流程侧栏＋报告工作区；工作区内报告身份/范围/来源状态 → 次级数量摘要 → 约55:45结论/证据双栏。手机：品牌栏 → 同一流程改横排 → 报告身份/范围/来源状态 → 数量摘要 → 结论列表及主操作区 → 所选条目证据 → 折叠信息。平板及窄桌面不满足双栏可读宽度时退单列。

## 选择与操作状态

- 初次进入：有条目时明确选中第一条，对应证据立即显示；无条目时显示空状态，不伪造政策结果。
- 选择其他条目：当前选择标记、证据标题/条数、主操作对象同时更新，旧证据不残留。`aria-pressed`表达当前选择，`aria-controls`绑定证据区；不是折叠菜单，不滥用`aria-expanded`。
- 看对应证据：移动端继续采用用户已确认的下方区域定位；桌面也聚焦同一证据区，无额外弹窗、抽屉或第二套阅读器。
- 主操作：作用于当前选中条目，并打开政策全文披露；不会暗中重新扫描或提交材料。范围/来源/覆盖和提取信息仍按真实字段展示。
- 返回：恢复最近触发按钮，保留所选项。选择边框预留宽度，切换不因加边框挤动内容。
- 待接入的真实异步流程：加载/失败/取消/恢复状态按现有业务；请求期间相关提交禁用并保留按钮位置、文字和上下文，结果失败就近说明，不用普通“已完成”掩盖局部未知。独立示例不假造网络请求或进度。

## 低成本复用与分工

本轮复用现有Vue、UiButton、StatusTag、InstrumentPanel及本地字体，只调整壳层、面板顺序、选择态与操作文案；不引入新组件库/全局状态库/路由/依赖。独立报告和组件页为可运行示范。DS将同规则应用到导入/候选/进度/报告/存档/设置与移动端，串行吸收#160既有业务，不重写已验证逻辑。

后续业务验收必须对真实生成契约、返回/恢复、未解锁步骤、NOT_DECLARED五前提及多来源状态取证；不能用此示例替代全流程完成。Android/WebView/IME/安全区/TalkBack与系统大字另取设备证据。本轮只验证Chromium与合成材料。

## 依据与验证方法

已读取显式调用的ui-ux-pro-max，针对导航/选择态/操作层级分别检索，并核对quick-reference的nav-hierarchy、nav-state-active、keyboard-nav、visual-hierarchy、compact-label-overflow与pro-rules的焦点、文字缩放、操作顺序。检索中“Active State”和键盘导航适用；未找到专门的证据阅读布局或按钮层级匹配，55:45、证据上下文与集中操作区是结合当前截图和用户目标作出的设计判断，不冒充技能数据库结论。Vue检索无额外状态库或生命周期改造需求，不因泛化命中增依赖。

专项检查五视口、320/390的200%根文字、空/未知/长文本、选择切换、关联引用排他性、主操作对象、元数据默认折叠/展开事实、焦点与返回、减少动效、原业务入口隔离；保留视口图与完整图并独立视觉审阅。原acceptance:frontend及权威npm run check继续验证业务回归与构建。更多设备、暗色主题不纳入本次白色示例的已验证范围。
