## 实施顺序与归属

1. PR #90 已补确认信息和确认后变化拒绝，并用旧 APK 的失败、新源码的实际设备成功对照；
   两种壳复用同一读取核心。历史收据保持原 SHA。
2. 本轮补独立受保护配置和失败关闭验证。原生实现与接口需和 #72 的生产使用方
   串行整合；当前不调用真实模型，不将配置存储成功视为模型直连已完成。
3. 真实 HTTPS/上传沿 #70 已有契约接入。#80 的 PR #112 已合入 main（本轮基线 a2e058a），
   #81 当前只交付部署基线，真实运行时/部署组合并未因接口票关闭而自动完成。
   不以 mock 上传或实验摘要冒充服务端包集合确认。
4. #72 的 PR #110 拥有生产 Web/报告/候选交互，本实验不修改它的共享页面。
   Android 基座接口稳定并合入后，由对应 owner 串行整合，禁止平行重造报告或上传实现。
5. 用户目前没有真机。真机、两实例真实 HTTPS、背压、恢复和材料去向证据是剩余门槛；
   #73 在 #80/#81 产物可用后组合验收，不以本实验关闭 #71。

本轮继续推进第 2 项并维护覆盖记录。PR #90 仍是部分交付，合并暂停；
不发布客户端、不部署服务，也不将整票标为完成。
