## 2. 环境修复（执行前，非产品代码）

首次在 `a1a6386` 上运行时 worker 镜像构建失败：`uv sync` 拉取 `opentelemetry-api` 等超时。定位为 WSL Docker 环境问题，不是产品回归：

1. `/etc/docker/daemon.json` 的 `proxies` 指向 `http://127.0.0.1:7897`（WSL NAT 内无监听）。
2. `/root/.docker/config.json` 与 `/home/oasis/.docker/config.json` 的 `proxies` 分别指向不可达的 `10.155.217.182:7898`、`172.20.10.3:7898`；Docker CLI 会把它们注入 build/run。
3. WSL eth0 MTU 1280 vs docker0 1500；`iptables -P FORWARD` 为 DROP（`docs/agents/local-environment.md` §4 记录的已知环境假失败）。
4. `registry-1.docker.io` 直连不可达（ghcr.io 可达），BuildKit 卡在 `docker.io/library/python` metadata。

修复与验证：daemon.json 去除代理、设 `mtu: 1280`、加可达镜像源 `docker.m.daocloud.io` / `docker.1ms.run`；两个 CLI 配置备份为 `*.bak-20261023T003347Z` 后置 `{}`；`iptables -P FORWARD ACCEPT`；重启 dockerd。实测容器 egress 可用（root/oasis 两种 CLI），pinned `python:3.12.13-slim` 与 `ghcr.io/astral-sh/uv:0.11.23` 均秒回。修复前 `a1a6386` 的失败日志保留为 `tmp/e2e/20261023/r01-run1-a1a6386-failed.log`、`r01-run2-dockerio-hang.log`（均为环境失败，不计产品结果）。
