## 1. 项目介绍（一页版）

> 本节整合自 Ticket 02「一页版项目介绍」（试读验收通过，2026-10-11）；可作为一页版独立使用。

PrivacyTrace 是一个面向普通 Android 用户的应用隐私**对照工具**。它只做一件事：读取 APK 中的隐私相关静态线索，把每条线索与隐私政策原文摆在一起，让你看到这些线索在代码与政策原文中的**具体位置**。

它**不判定**应用是否合规、数据是否真的被取用——做不到，也不打算做。它给你一份**摊开的证据**：哪些敏感能力被声明、哪些调用线索出现在哪里、政策原文有没有提到这类数据。**怎么判断，留给你。**

> 例：报告写的是「申请了读取相册的能力」「出现了一处相关调用线索」，而**不会**写「这个应用偷看了你的相册」。

分析范围覆盖定位、标识、联系人、相机、麦克风、文件与媒体（含截屏）。

### 给谁用

普通 Android 用户——不要求会读代码或法务文本。目标是把专业级、多源、可追溯的隐私证据，变成普通用户**能理解、能自己复核**的隐私体检。

代码与政策的一致性分析**并非本项目率先提出**；着力点在**可理解**与**可复核**。

### 凭什么可复核

1. **结论指得到原点**：报告按「概览 → 按来源对照 → 证据下钻」组织；线索能定位到代码里的具体位置，并与政策原文原句对照。
2. **事实、声明、推断分开**：权限是**能力声明**，调用是**静态线索**，都不等于「行为真的发生了」；未证实的信息如实保留为 `UNKNOWN`。
3. **真实样本留有记录**：真实样本分析（GKD v1.12.1）保留了两次独立隔离运行的复现校验（同一环境、同一路径）。
4. **验证入口公开**：仓库提供统一检查脚本（`scripts/check.sh` / `scripts/check.ps1`），任何人都能照文档复跑。

### 它明确不做什么

- **只对照，不判定**：不判定应用是否合规，不判定数据是否真的被取用——线索不等于行为。
- **不推断数据流向**：不判定是否向第三方传输。
- **不自动理解政策**：政策文本及候选声明默认由人工准备，确定性规则负责对照；2026-10-12 起另提供**可选、默认关闭**的大模型辅助抽取插件（[PR #42](https://github.com/MrEcho114/PrivacyTrace/pull/42)，[Issue #21](https://github.com/MrEcho114/PrivacyTrace/issues/21)）——模型候选保持 `UNREVIEWED`、不参与最终事实裁决；受控评测与离线交付**均未启用**该插件。
- **识别限于有限规则的静态分析**：没有精度或召回类指标；未命中规则不代表没有隐私行为。
- **不做动态抓包**：不做用户行为实验。
- **仅在本机运行**：接口只绑定回环地址，无身份认证，不可部署到公网。

## 2. 怎么自己复核（操作路径）

> 本节整合自 Ticket 03「证据可复核路径」（非作者实走通过，2026-10-11）。

**从报告里的一条线索出发，走到两个终点：**

1. **代码位置** —— 这条线索来自哪里（文件 / 方法 / 偏移 / 目标 API）
2. **政策原句** —— 这条线索被拿来和政策的**哪一句话**对照

目标：你可以**自己走一遍**，不必相信任何人的转述。走完你会得到几个可以自己验算的数字（偏移量），而不是一句"我核对过了"。

---

### 第 0 步：先分清三种"看报告"的方式

| 方式 | 是什么 | 需要准备什么 | 产出 / 用途 |
| --- | --- | --- | --- |
| **演示报告（合成样本）** | 仓库自带的人工构造样本 `samples/demo/evaluation-input.json` | 只要仓库文件（看数据用文本编辑器即可；看页面需启动服务） | 用来**练习核对动作**。**它不是 APK 扫描结果**，所有片段与政策均为人工构造 |
| **实时分析** | 真跑一次：宿主 CLI 调用 Docker 隔离容器扫描 APK | Docker + Worker 镜像 + APK 文件 + 政策文本 | **生成一个新作业**，写入 `data/jobs/{job_id}.json` |
| **离线回放（本机）** | 打开一份**已保存**的作业报告（不重跑扫描） | 已有作业文件 + 启动服务 | 与保存时一致的报告；用于事后复核，**不依赖重新扫描** |
| **受控离线包回放**（#18 交付物） | 打开**已验收的离线交付包**：不重跑、不连网、不需要 Docker | Python 3.11+ 与浏览器（不随包分发）；包内自带 viewer | 六份受控报告 + 三方案对照表；**与验收版本一致**，详见「路径 E」 |

> 「离线回放」（本机）是**为区分而使用的说法**；仓库中对应的入口是 `GET /api/v1/jobs/{job_id}/report` 与页面「报告来源」下拉里的作业选项。作业保存在 `data/jobs/` 目录，服务重启后仍可读取（该行为在 2026-10-09 的真实样本验证中实测过，见 `docs/stages/s1-pr29-real-sample-verification-20261009.md`）。最后一行（受控离线包）是**独立验收的外部交付物**，与前两行的"本机查看"不要混同。

**为什么这个区分重要**：
- 实时分析是"**生成**"：需要 Docker 与样本文件，一次扫描产生一份新作业；
- 离线回放（本机）是"**查看**"：任何人重新启动服务，都能打开同一份作业，看到与保存时一致的报告——这是"可复核"能成立的前提之一；
- 演示报告是"**练习**"：它的数据是合成的，核对链路走通 ≠ 对某个真实应用的结论；
- 受控离线包回放是"**按验收版本查证**"：看到的就是 #18 验收绑定的那六份受控报告（含独立 viewer 与启动前文件校验），适合演示与第三方复核。

### 路径 A · 跟着走一遍（零依赖，只需文本编辑器）

**准备**：克隆仓库，用任意文本编辑器打开 `samples/demo/evaluation-input.json`（254 行）。
**不需要**安装任何软件、不需要启动服务。

#### A1. 挑一条线索

文件里 `behaviors` 段（可搜索 `"behaviors"`）是"行为线索"列表。取第一条：

| 字段 | 值 |
| --- | --- |
| `id` | `behavior-location` |
| `data_type` | `PRECISE_LOCATION`（精确位置） |
| `action` | `ACCESS` |
| `evidence_ids` | `ev-location-permission`、`ev-location-api` |

**它说**：这条线索涉及"精确位置"的"访问"，由两条证据支撑。

#### A2. 走到"代码位置"

在 `evidence` 段（可搜索 `ev-location-api`）找到这条证据：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `source` | `synthetic/LocationFeature.java` | 线索来自哪个文件 |
| `locator` | `LocationFeature#readGpsLocation:12` | 文件里的具体位置：类 `#` 方法 `:` 行 |
| `api_call.target_descriptor` | `Landroid/location/LocationManager;->getLastKnownLocation(Ljava/lang/String;)Landroid/location/Location;` | 静态分析定位到的目标 API（JVM 描述符写法） |
| `api_call.rule_id` | `android.location.last-known.gps` | 命中的规则编号 |
| `api_call.context` | `{"provider": "gps"}` | 该次命中的静态上下文 |
| `excerpt` | `locationManager.getLastKnownLocation(LocationManager.GPS_PROVIDER);` | 该位置的代码片段 |

→ **这就是"代码位置"**：回到 `samples/demo/evaluation-input.json` 里核验这条证据的 `source` / `locator` / `excerpt` 三个字段（即上表读到的值）。**注意：demo 是合成样本——`synthetic/…` 是构造出来的虚拟路径，仓库中没有这个文件，也没有可以打开的源码**；真实 APK 的字节码位置请看**路径 C**。
→ 注意它标注了 `status: STATIC_POTENTIAL`：这是一条**静态潜在**线索，不代表运行时真的发生。

#### A3. 走到"政策原句"

线索的对照对象在 `policy_claims` 段（可搜索 `claim-policy-in-app-location`）：

| 字段 | 值 |
| --- | --- |
| `document_id` | `policy-in-app`（声明来源） |
| `data_type` | `LOCATION` |
| `declared_purpose` | `提供地图功能` |
| `evidence_ids` | `ev-policy-in-app-location-sentence` |

顺着 `evidence_ids` 找到这条政策原句证据（可搜索 `ev-policy-in-app-location-sentence`）：

| 字段 | 值 |
| --- | --- |
| `excerpt` | 我们访问位置信息，用于提供地图功能。 |
| `start_offset` / `end_offset` | `0` / `18`（按 **Unicode 码点**计数，半开区间 `[start, end)`） |
| `document_id` | `policy-in-app` |

#### A4. 自己验算（**关键一步，不要只信 excerpt**）

打开 `policy_documents` 段里 id 为 `policy-in-app` 的条目（可搜索 `示例 App 内隐私政策`），取 `artifact.text`：

```
我们访问位置信息，用于提供地图功能。其他功能使用必要的应用配置。
```

**验算**：从第 0 个码点切到第 18 个码点，得到什么？

```python
text = "我们访问位置信息，用于提供地图功能。其他功能使用必要的应用配置。"
print(text[0:18])   # 预期输出：我们访问位置信息，用于提供地图功能。
```

若输出 = 证据里的 `excerpt`，说明：**这条原句确实存在于政策全文的那个位置**，偏移量对得上。
（2026-10-11 已实测：`text[0:18]` 输出与 `excerpt` 完全一致。）

#### A5. 再走一条（换一个政策来源）

用 `behavior-oaid` 再走一遍全过程：

`behavior-oaid` → `ev-oaid-api`（`DeviceFeature#readDemoOaid:21`，注意 excerpt 自带标注 `artificial fixture, not a real SDK API`）→ `claim-store-oaid` → `ev-store-oaid-sentence`：

| 字段 | 值 |
| --- | --- |
| `excerpt` | 我们访问OAID，用于统计。 |
| `start_offset` / `end_offset` | `18` / `32` |

**验算**：换到 `policy-store` 的 `artifact.text`（"我们访问位置信息，用于提供地图功能。我们访问OAID，用于统计。"），切 `[18:32]` → 预期输出「我们访问OAID，用于统计。」（已实测一致。）

注意这条的政策来源是 `policy-store`（**另一个独立来源**），切的是**另一份**全文——政策不被拼接，一个来源一份快照。

#### A6. 你刚刚验证了什么、没验证什么

**已验证**：
- 每条线索都能沿 ID 链走到它的位置（代码侧 / 政策侧）；
- 政策原句的偏移量是可**自行切算**的（不依赖作者的话）。

**未验证（必须知道）**：
- 这条线索**不代表**该应用实际做了这个访问——静态线索 ≠ 运行时行为；
- demo 是**合成样本**：`synthetic/…` 是构造出来的**虚拟路径，仓库中没有这些文件**，不是真实 APK；本路径验证的是**核对机制能走通**。

### 路径 B · 在页面 / 接口上走同一步（需要启动服务）

**首次准备**（干净环境只需做一次，完整步骤见 `README.md`「启动演示服务」）：

```bash
npm ci
uv sync --project apps/api --locked --extra worker
```

**启动**（两条命令分别在两个终端）：

```bash
# 终端 1：后端（127.0.0.1:8000）
uv run --project apps/api --locked --extra worker uvicorn privacytrace.main:app --host 127.0.0.1 --port 8000
# 终端 2：前端（127.0.0.1:5173）
npm run dev
```

**页面路径**（打开 `http://127.0.0.1:5173`）：

1. 「报告来源」下拉框选第一项 **`SYNTHETIC · 人工构造示例`**；
2. 页面出现「隐私声明对照」表，点某一行右侧的 **「查看 N 条证据 →」** 按钮 → 展开证据卡片（**第 1 次点击**）；
3. 证据卡片里能直接看到：`source · locator`、目标 API、以及政策原句的**高亮片段**与「原文位置：[0, 18)，按 Unicode 码点计数」；
4. 点证据卡片里的 **「完整政策与适用边界」** → 跳到下方「报告版本、权限与全部政策快照」区，展开该政策的**全文**（**第 2 次点击**）——在全文里找到高亮那句话的位置。

**预期输出（2026-10-11 用规则引擎实测）**：demo 报告共 **7 行结论**：

| # | 隐私数据 | 结论（页面文案） | 是否待复核 |
| --- | --- | --- | --- |
| 1 | 精确位置 | 声明粒度不足（App 内政策） | 待复核 |
| 2 | 精确位置 | 声明粒度不足（应用商店） | 待复核 |
| 3 | 通讯录 | 未找到对应声明（App 内政策） | 待复核 |
| 4 | 通讯录 | 未找到对应声明（应用商店） | 待复核 |
| 5 | OAID | 未找到对应声明（App 内政策） | 待复核 |
| 6 | OAID | 具体类型已声明（应用商店） | —— |
| 7 | OAID | 不同来源声明有差异 | 待复核 |

**不用页面也可以（接口路径）**：

```bash

# 取单条证据
```

**页面文案的边界**（页面自带说明，摘录）：六种状态只对照"数据类型是否被声明"；"具体类型已声明"**不代表**目的、接收方、传输或时间范围一致，**更不是合法性判断**。

### 路径 E · 受控离线包回放（#18 已验收交付物，2026-10-13）

这是**不依赖 Docker 与源码搭建的已验收回放入口**：不重跑扫描、不连网、不需要安装 Node / API 服务 / 模型密钥，用交付包内自带的 viewer 直接查看**六份受控报告**与三方案对照表。

**怎么用**（完整指引见包内文档与 `docs/stages/pt904-offline-delivery.md`）：

1. 获取包：从 [artifact 下载](https://github.com/MrEcho114/PrivacyTrace/actions/runs/38402665810/artifacts/11815363602)（GitHub 上有效至 2026-10-27）或经哈希核对的内部归档副本；解压后实算 ZIP SHA256 核对；
2. 联网准备阶段：预装 **Python 3.11+** 与浏览器（二者不随包分发），把 `offline/` 目录复制到目标环境；
3. 断网后，在 `offline/` 目录内启动 viewer：

   ```bash
   python -B viewer.py --port 8765
   ```

   浏览器打开 `http://127.0.0.1:8765`。viewer 启动前会校验文件集合与 SHA-256——新增、遗漏或被篡改的文件会被拒绝启动；
4. 可查看：六份受控报告的来源切换与证据展开、`/comparison.html` 三方案对照表（原始数据在 `offline/comparison.json`）。

**边界（必须分清）**：
- 这是**回放**，不是实时扫描：不重新分析任何 APK、不调用外部模型；
- 包内是**自建受控材料**（六个源码场景），不是商业 App；不含 GKD 真实 APK 或真实政策全文；
- 回放结果绑定交付 SHA 与包哈希；**该 SHA / 包后续如有变化，须重验受影响路径**；
- 内部限定验收，不含公开分发授权。
