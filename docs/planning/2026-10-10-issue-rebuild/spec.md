## Problem Statement

现有计划还在重复安排已经完成的 S1，缺少受控评测入口与独立真值的工作量；任务依赖只存在正文，构建、评测、界面和离线验收的顺序不够明确。团队需要在10/17内部冻结前交付可验证作品，重点是静态证据可追溯与缺证据时谨慎降级。

## Solution

复用已合并 S1 的本地 CLI、隔离扫描、人工政策摄取、JSON 作业存档、HTTP 和浏览器下钻。先打通 C02/C06 两个真实源码编译场景，再扩至六场景，在相同输入下比较三方案，完成实际浏览器异常矩阵和干净环境离线回放。

一份既有 GKD 案例展示真实应用链路；六个自建场景提供可独立核对的预期答案。真实样本与受控样本、工程回归与评测、实时扫描与离线回放分别记录。

## User Stories

1. 作为报告阅读者，我能从判定定位到代码/权限及政策原句，理解静态线索的边界。
2. 作为阅读者，我能区分真实样本、受控场景和合成示例。
3. 作为阅读者，我能看清政策/适用信息未知时的证据不足。
4. 作为开发者，我能用锁定环境从源码编译受控 APK，并记录产物哈希。
5. 作为评测者，我在运行前冻结独立真值，且被测算法只能读输入材料。
6. 作为评测者，我用三方案处理同一份材料，记录差异、错误和弃判。
7. 作为评测者，我单列人工准备候选的工作量，不归功于自动政策理解。
8. 作为演示者，我在浏览器查看受控输出与异常提示，明确回放来源和生成时点。
9. 作为交付者，我能在预先说明的干净环境中断网启动与回放，并验证包内清单。
10. 作为团队负责人，我能从工单依赖与验收证据看见哪些任务现在可以领取。
11. 作为材料整理者，我能根据实际输出填写贡献、许可、AI 使用和限制。
12. 作为负责人，我按已核实校内/赛项要求提交并私下保存回执。

## Implementation Decisions

- 遵守 ADR0001：本地 CLI 分析 + 浏览器报告。本期不增加网页 APK 上传或多人公网服务。
- 遵守 ADR0002：受控输入单独标识；仅使用实际核对的自建版本、适用范围与政策事实。真实未知地区/政策状态不补造，旧报告不改。
- 复用隔离扫描、结构化候选摄取、确定性规则评估与报告契约。数据格式在 PT-910 内设计；不先开一组横向重构任务。
- 候选声明是输入，预期状态是标签；分别存放。真值在运行前冻结并记录版本/哈希；算法不读取标签，比较器只在运行后使用。
- 政策核验与阶段接受分别记录，不恢复已撤销的 S1 双人评论/签字门槛。
- 三方案为权限+关键词、同一 API 证据/完整描述符+扁平匹配、本系统规则对照。统一材料开放与使用说明；不故意削弱基线。
- 首张 PT-910 打通 C02/C06 两场景；#16 扩展其余四场景，#25 汇总正式六场景比较，#17 并行处理已交付链路的浏览器异常。
- #18 首次离线验收前移至10/16；10/17冻结的是代码，后续修阻塞问题时记录新 SHA 并重验受影响交付包。
- 岗位安排：用户本人负责受控输入、公平评测与整合；两位技术队友分担源码构建、浏览器与离线交付，具体人/工时未知。辅助成员整理材料，不裁定技术事实。
- 阶段工单负责汇总。保留原25个编号及并行新规范#30，只新建一个最小闭环任务；不重复创建S0/S1或规范Issue，不恢复已取消门槛。

## 六个受控场景

| ID | 样本与政策关系 | 预期 |
|---|---|---|
| C01 | 权限存在，无对应敏感调用 | INSUFFICIENT_EVIDENCE |
| C02 | 静态调用与明确数据类型声明对应 | EXACT_MATCH |
| C03 | 声明只覆盖上位类别 | CATEGORY_MATCH |
| C04 | 实际核对、完整且适用的政策无对应声明 | NOT_DECLARED |
| C05 | 否定描述与静态调用并存 | AMBIGUOUS_DISCLOSURE |
| C06 | 政策或适用信息不完整 | INSUFFICIENT_EVIDENCE |

覆盖5类状态。C05不证明承诺被违反；C04不得仅因关键词缺失输出未声明。C07多来源冲突、C08 Multidex只在保底稳定后追加，不阻塞主线；既有工程回归不等于独立受控场景交付。

## Testing Decisions

最高层验收路径为 **源码构建 APK → 隔离 CLI 扫描/受控输入 → 报告 → HTTP/浏览器**。六场景比较器沿同一路径使用三方案的实际输出，不另造绕过扫描的结果。浏览器及断网回放是该报告路径的使用验收。

复用现有 CLI/HTTP/规则/契约与浏览器回归入口。必要负例：输入不完整仍降级、算法读不到标签、真实输入不能被受控适配全局放宽、报告定位引用失效、异常/取消/长文本/纯文本渲染。不以实现细节测试或工程用例数替代评测规模。

工程检查采用最新 main 权威入口 `bash scripts/check.sh`（Windows包装入口委托同一脚本），包含 API/Web 回归、Ruff、契约零差异、类型/构建及 CI Docker 分支；结果绑定交付 SHA。启动实现前恢复最新检查入口，旧本地分支脚本不能当作权威入口。

评测输出包括逐场景预期/实际、映射与定位核对、状态比较、全样本覆盖/失败/弃判、实际耗时和人工准备时间。先固化计数单位与可测目标，再计算必要的 P/R/F1；零分母 N/A。六个小样本不作统计代表性、商业 App 全局召回或自动抽取准确率宣称。
