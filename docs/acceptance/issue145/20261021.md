# Issue #145 验收记录 · 交互状态与无障碍

日期：2026-10-21。任务：[#145](https://github.com/MrEcho114/PrivacyTrace/issues/145)，父票 [#141](https://github.com/MrEcho114/PrivacyTrace/issues/141)。分支 `codex/issue145-states-a11y`，基线 `main` `b5b7237`（含 #142/PR #150）。设计与状态盘点见 [issue145-interaction-states.md](../../design/issue145-interaction-states.md)。

## 结果摘要

- 修正了轮询导致任务卡卸载、重复播报与焦点丢失；手动刷新不再关闭已打开的证据面板。
- 初始加载、错误、运行任务、忙碌、删除确认的 live region 不再嵌交互控件；删除确认具备名称、打开焦点、Esc、Tab 顺序和焦点返回。
- 设置、证据预览、删除确认、完整政策跳转的焦点路径按键盘验证；失败/取消/重试后的焦点落到可读结果或状态卡。
- 导入 APK 错误与输入关联；设置保存失败与成功分开为 alert/status；示例全文开关补 `aria-expanded`。
- 关闭页面上会阻塞 `aria-hidden` 的手写 `aria-live`，恢复设置模态打开时应用主体的 `aria-hidden` 隔离，并由 `role=status/alert` 的隐式语义承担播报。
- 手机后台轮询使用 epoch 失效规则：取消、重试、换实例、删除或任何前台操作都会使旧轮询结果失效，迟到结果不再复活任务或覆盖新错误。
- 未新增依赖、组件库、业务状态机或动效参数。

新增脚本 `scripts/verify-issue145-a11y.cjs` 的检查项：

1. 初始加载：`role=status` 文字存在，live region 内没有按钮；停止按钮在区域外。
2. 运行中轮询：4.2 秒、约 40 个采样点上任务卡持续挂载；未变化轮询不产生状态播报。
3. 真实状态变化只播报一次；重复刷新同一状态不再播报；焦点不落到 body。
4. 自然进入终态时，被移除的“取消任务”焦点回到任务状态卡。
5. AI 披露文字对比度 5.08:1（此前硬编码 `#7d8d81` 为 3.21:1）。
6. 证据面板：手动刷新后仍打开、选中项不变；收起后焦点回到触发行。
7. 删除确认：命名 group + 说明、打开聚焦确认、Esc 取消、Tab 顺序、取消/完成焦点返回、结果消息可聚焦、迟到轮询不复活。
8. 加载失败：alert 文字与重试按钮分离；重试成功从被移除的重试按钮恢复焦点。
9. 设置：可访问名称/描述、初始关闭焦点、Tab 陷阱、Esc 关闭、焦点返回触发点、背景 `aria-hidden`。
10. 导入 APK 错误：`aria-invalid` + `aria-describedby` 关联；AX tree 暴露 alert 与错误文字；隐藏输入聚焦时文件区有可见轮廓。
11. 忙碌：status 内无控件；停止按钮在区域外；取消后有持久文字说明；焦点恢复。
12. 对比度与可见焦点：见下表，全部达到 WCAG AA 文本 4.5:1 / 非文本 3:1。
13. 初次加载失败后重试：错误清除、焦点从被移除的重试按钮恢复。
14. 切换来源失败后重试：保留当前来源，重试恢复焦点。

## 键盘与焦点路径

| 路径 | 验证 |
| --- | --- |
| 跳到内容 → 工作台 | `Tab` 显示跳转链接，Enter 聚焦 `#workspace-content`；既有验收 |
| 导入 → 候选 → 进度 → 报告（示例） | 仅键盘 Enter/Tab 走完；既有验收 |
| 打开设置 | Enter 打开；焦点到“关闭”；Tab 留在对话框；Esc 关闭并回到“项目设置” |
| 删除确认 | 聚焦“删除任务”后 Enter；焦点到“确认删除”；Esc 取消并回“删除任务”；Tab 到“取消删除”后 Enter 同样返回 |
| 证据预览 | 点开/键盘打开后聚焦面板；收起/关闭回原按钮；示例报告窄屏同样返回 |
| 任务取消/重试/删除 | 触发按钮消失时焦点回到任务状态卡或结果消息，不留在 body；自然轮询进入终态同样恢复 |
| 页面级错误重试 | 重试成功、错误区消失后焦点回到任务状态卡或刷新按钮，不留在 body |
| 运行任务轮询 | 前台焦点保持在原控件；不因轮询打开面板、改变选择或滚动位置 |
