Section one

这个工具给证据，不给合规结论

定位、用户、三条不做的事

第一节回答一个问题：这个作品做什么。后面的创新和边界都从这里长出来。

§1 · 定位

范围、用户与三条边界

摘要. PrivacyTrace 读取 Android 安装包里能静态看到的隐私线索，与隐私政策原文逐条对照；每条结论都带代码位置与政策原句。它只回答「代码里有没有这个线索、政策里有没有这句话」，不回答「应用是否合规、是否安全、是否实际采集」。

给谁

普通 Android 用户。不用会读代码，也不用懂法务文本。报告给出线索位置和政策原句，读者可以自己复核。

分析范围

定位、标识、联系人、相机、麦克风、文件与媒体（含截屏）。APK 支持单包，也支持 base + 全部 splits。

明确不做

  • 不判定合规、安全或违法
  • 不推断是否向第三方传输
  • 不做动态抓包，不自动理解政策

形态：Android 客户端、Web 工作台、隔离扫描 API、离线只读回放。分析只在本机或受控内网运行，没有公网实例。

三条「不做」属于产品定位，把判定权留给用户。三张卡片对应受众、范围和边界。

§2 · 创新一

双向证据链：结论必须能回到两侧原点

Figure 2：代码侧与政策侧各自独立取证，在 PrivacyIssue 汇合；任何一侧缺失，结论只能是「证据不足」。

真实样本：GKD v1.12.1（2026-10-09 记录）

ev-887b01d4… · classes.dex Lr2;->p · offset_bytes = 2 → AccessibilityService.takeScreenshot policy-sentence-1 · [363, 423) 条件：「仅调试」 判定：INSUFFICIENT_EVIDENCE
  • 两侧都能自己走：代码侧看文件、方法、偏移和目标 API；政策侧看全文和码点区间。
  • 区间按 Unicode 码点、半开区间；切出来的必须与原句一致。
  • 无法证明的参数保持 UNKNOWN，不用推断补全。
真实样本里，代码侧给字节码偏移和目标描述符，政策侧给码点区间。两侧对不上，结论只能是证据不足。

§2 · 创新二

证据不足也是一种结论

层级我们写下我们不会写
权限能力声明 CAPABILITY_ONLY：「申请了读取相册的能力」「偷看了相册」
调用静态线索 STATIC_POTENTIAL：「出现一处相关调用线索」「已采集 / 已上传」
政策声明状态（UNREVIEWED / PARTIAL）与原文区间「政策合规」
对照六类状态之一；证据不够就是 INSUFFICIENT_EVIDENCE「违法 / 不安全」
未知保留 UNKNOWN：目的、接收方、跨境、期限推测出一个答案

「未命中规则不代表没有隐私行为。」（项目能力边界）

六类状态只对照「数据类型是否被声明」。「具体类型已声明」不代表目的、接收方、传输或时间范围一致，更不是合法性判断。

创新点在识别不出时怎么写。证据不足是一等状态，不用推断补齐。

P / R / F1 按协议为 N/A。没有「实际采集 / 合法性」的二元真值，就不在事后设正类；指标只报状态一致数、失败与弃判。

§2 · 创新四

隔离执行与断网回放：限制写在参数里

扫描容器：未知 APK 只在受限环境里解析

user 65534（非 root） network none read-only rootfs cap-drop ALL 1 CPU · 1 GiB · PID 32

扫描退出后清理运行目录，并用 docker inspect 复核容器参数；宿主机只负责调用，不在宿主机解析未知 APK。

离线回放：打开前先验包

  • 包内 viewer 启动前校验文件集合与 SHA-256；新增、遗漏、篡改即拒绝启动。
  • 不重跑扫描、不连网、不需要 Docker 或额外服务。
  • 24 个成员 / 3,056,905 B；结果绑定交付 SHA，可在断网环境复现。

回放不重扫：打开包只还原已保存的报告与证据，不调用分析链路。

隔离参数是执行约束，不是安全认证。回放包只做内部限定验收，不含公开分发授权。两项都不能替代真实应用评测。

这一项让评审能复核。扫描在受限容器里跑，交付包打开前先验哈希；参数写在代码和文档里。

§3 · 工作流

从材料到报告：六步，每一步都有状态

  1. 材料：APK（单包或 base+splits）和政策来源。来源可自动发现、网页辅助或手工导入。
  2. 候选：政策候选默认人工准备。模型候选标 UNREVIEWED，不参与最终裁决。
  3. 确认：用户确认包集合、上传范围与政策候选；取消与返回都不改变草稿原状态。
  4. 扫描：仅未知 APK 进入隔离 Worker；本机或部署模式使用同一套扫描参数。
  5. 对照：确定性规则输出六类状态；事实、声明、推断分开存放。
  6. 报告：概览 → 按来源对照 → 证据下钻；可导出、可离线回放。

四种证据，分开存放

层级能证明不能证明
工程测试代码按预期运行APK 分析有效性
受控评测自建场景下的名义对齐真实 App 表现
真实样本个案链路跑通全局精度 / 召回
正式提交系统受理工程验收

这张表管住每个数字的措辞：测试通过不写成评测通过，上传成功不写成提交成功。

六步的状态都以页面文字呈现；颜色只是冗余编码，不从颜色推断结论。

工作流不复杂。难的是每一步状态都不能悄悄跳过。右边这张表是全稿的引用口径：任何数字先问它属于哪一层证据。
