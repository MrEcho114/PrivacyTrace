## 5. F08–F10 判定：NOT_RUN

评估结论：**三项均未执行（NOT_RUN）**，不是产品通过。依据与缺失前置如下。

- **入口形态**：`deploy/acceptance/{capacity_drill,backup_drill,fault_drill}.py` 不是可 `python3 -m …`
  运行的 CLI；它们是 `r6_capacity_audit` / `r5_backup_recovery` / `r4_fault_recovery` 收集器的库函数
  （`admission/queue/disk(lab, topology)`、`drill(lab, topology)`、`operations_drills.*`）。现有文档路径是
  `deploy/check_acceptance.sh` → `deploy.acceptance.provision`（**两个**实验室）+ `laboratory.py`，
  由该流程设置 `PT_ACCEPTANCE_*` 拓扑变量并生成收据。本 lane 使用的是单实验室 F134 驱动路径，
  没有与之匹配的既有单实验室 CLI；手写驱动不属于「按现有文档执行」，且需要额外时间。
- **F08 容量**：需 `r6` 收集器 + `Sampler` 指标 + 多个真实 client 容器占用实验室 pinned api 子网，
  并跑 draft 准入、队列背压、512 MiB tmpfs 测试盘三类预算。前置与时长（>30 分钟，含并发测量轮次）
  超出本 lane 时间盒（北京 10:45 交付）。
- **F09 备份/恢复**：需 `r5` 收集器 + `backup_drill.drill`（停 web/api/worker/dispatcher/gateway、
  备份、建独立恢复库、恢复读回、删除重放）。会停 5 个角色并新建数据库，需专门驱动与回读，
  未在时间盒内执行。
- **F10 升级/回滚、凭据轮换、磁盘满恢复**：同属 `r5` 的 `operations_drills`；其中
  `upgrade_rollback` 还要求 `PT_ACCEPTANCE_PREVIOUS_API_IMAGE`（上一基线 API 镜像），本 lane **未构建**
  上一基线镜像（本轮只构建 83a7983 四镜像），因此该子项缺可升级的「前一版本」镜像；凭据轮换与
  `disk_full`（512 MiB tmpfs）会破坏实验室状态，需在 F01–F07 之后专门执行。
- 三项均建议由 R04 部署专项 lane 在其两实验室 harness 中正式执行并出收据；本回执不重复、也不
  伪称通过。
