# Core Workflow：任务与交付

> 本文件只定义日常任务治理。权限、发布和破坏性外部操作按需读取
> `core/policy.md`；工具命令按 Context Router 读取对应参考，不在这里复制。

## 0. 治理所有权

TheMasterplan 只在自己是当前任务的交付治理所有者时工作。

直接使用编辑器、Shell、Git/jj、OpenCode、Codex、ChatGPT、测试或构建工具本身
不构成冲突。若当前上下文明确表明另一个系统已经拥有 worker/session、任务
workspace/worktree/branch、Issue→PR 状态机、CI/review 路由或
merge/release/deploy 生命周期，则：

```text
TheMasterplan: ABSTAINED — external delivery workflow owns this task.
```

`ABSTAINED` 是任务级瞬时状态，不写入 `.themasterplan/state.json`。不要按品牌、
目录名或版本猜测外部所有权，也不要为外部 orchestrator 建兼容层。

## 1. 任务与范围

- 复杂任务：使用 Issue 记录目标、范围、验收条件与排除项。
- 小型低风险任务：可以使用当前会话中的明确人类授权；PR 记录授权来源、目标、
  范围。
- 微小修复快速通道：仅限目标清晰、无范围争议、单文件或极少数同主题文件、
  约 ≤30 行、只涉及文档/配置/测试/注释、不触及核心逻辑或公共接口、不涉及
  持久化数据/部署/发布/远端数据/破坏性操作，并且验证与最终 diff 均正常。
  需要针对该修复的会话内明确授权；不满足任一条件就走普通 PR 路径。
- 无 Issue 时不得伪造编号。
- 实现需要实质扩大范围时，停止并请求新的范围决定。

允许研究、实现、检查子代理与多个模型参与，但只有一个主交付责任人控制最终
范围、VCS、最终验证、push、PR 与人类交接。子代理不独立执行外部交付写操作。

## 2. 默认继续与完成

在授权范围内，默认继续完成安全的本地工作：

```text
读取相关文件
实现/编辑
格式化、lint、测试
修复本次改动造成的失败
重跑受影响验证
检查工作区与最终 diff
准备交付材料
```

不要在第一次实现后仅因为“可以让人审阅”而提前结束；以根部 `AGENTS.md`
Completion Contract 为完成定义。

## 3. 工作区、验证与 diff

- 开始写入前确认任务来源、工作区归属和未知本地修改；不覆盖来源不明的修改。
- 一个任务对应一个可验证 change/短生命周期任务引用，不混入无关修改。
- push 前运行根部 `AGENTS.md` 记录的权威验证入口，并阅读完整最终 diff。
- 验证失败时，修复由本次改动造成的问题并重跑相关验证；不得把失败或未执行
  的验证表述为通过。
- 基线、任务引用或远端 ref 冲突且正确目标不明确时停止，不猜测、不强推。

## 4. Pull Request 交付

普通 PR 使用仓库 `.github/pull_request_template.md`，让模板与 CI validator
作为机械契约的单一事实来源；不要在 Skill 或其他入口复制字段清单。

创建或更新 PR 后：

- 等待关联 CI；
- CI 因本次修改失败时继续修复并重跑；
- CI 通过后再报告 PR 已准备好供人类决定是否合并；
- 合并后的 Agent 自建任务分支按 `core/policy.md` §7.1 处理清理。

## 5. 真正的停止边界

以下情况才需要停止并取得人类决定或重新授权：

- 安全、隐私、合规、Secret 或数据风险；
- 任务范围发生实质扩大；
- merge/release/deploy/受保护分支推进缺少所需授权；
- 需要强推、移动/覆盖已发布 Tag、覆盖未知人工修改；
- 远端 ref、候选 SHA 或已批准状态发生冲突/变化；
- 外部交付工作流已拥有当前任务；
- 继续操作将跨越 `core/policy.md` 定义的破坏性或发布边界。

## 6. 卫生与审查

最终 diff 不应包含误删、范围外变更、调试代码、临时文件、缓存或无关生成物。

代码审查意见只使用三类：

```text
合并前必须修复
建议本次修复
可以后续处理
```

每条意见说明具体问题、影响和需要的修复。
