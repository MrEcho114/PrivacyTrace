# S1 隔离扫描的数据生命周期与覆盖边界

针对 PR #27 Review `5457877086` 的三条意见。此策略不代替 A/B 人工证据复核。

## 默认不留存 APK 副本

- 仅对本次创建的 UUID 工作区操作。先预留容量，再复制为不可变 `input.apk` 并挂载单个文件；绝不删除调用者的原始 APK。
- 复制、路径转换、镜像检查、创建、运行、取消、超时和输出校验均在清理保障内。常规退出后删除 `input.apk`，不留存原始 worker stdout/stderr。
- 留存受限 `isolation.json`：哈希、镜像 ID、隔离配置、容器清理核验、输入删除状态、主错误及清理错误。不包含 APK、完整政策或原始诊断日志。
- 不提供长期保留原件的开关。复核若需要原件，由授权人员保管调用者已有的原件；此运行器副本的正常保留期限仅为本次扫描生命周期。
- 若容器、输入文件、收据或配额预留清理失败，CLI 返回失败且报告清理错误，不宣称已清理。失败预留保持计费。强制杀进程、断电或系统拒绝文件删除无法保证即时清理，需人工处理残留。

## 累计容量与访问控制

- 默认根目录为 `tmp/apk-runs`，累计文件预算 **1 GiB**。历史文件和活跃运行预留都计入预算；每次扫描为 APK 大小加 256 KiB 收据空间预留容量，跨进程文件锁保护检查与预留。
- 使用 `PRIVACYTRACE_APK_RUN_ROOT` 和 `PRIVACYTRACE_APK_RUN_QUOTA_BYTES` 配置 CLI/流水线；直接扫描 CLI 也提供 `--run-root`、`--quota-bytes`。预算必须为正整数。
- 预算不足在复制前返回 `STORAGE_QUOTA_EXCEEDED`，不删除旧收据，也不启动容器。默认模式并不表示审计永久不限量存储；保留多久由授权人员按复核需求决定，容量达到上限后人工归档/清理再继续。
- POSIX 下根目录须归当前用户所有，根与新运行目录为 0700、锁和收据为 0600。Windows 的目录 ACL 继承由系统管理，部署者必须选用仅当前用户及必要系统主体可访问的私有目录，并检查继承权限；`chmod` 清除只读属性不是 Windows ACL 隔离承诺。禁止使用共享目录、公网服务或不可信链接路径。
- 可用本地 `--cancel-file <path>` 请求取消；HTTP 流水线仍使用原有取消接口。它是本机协作信号，不是认证机制。

## 历史目录不自动迁移或删除

已有 `tmp/apk-runs/*/input.apk`、旧 stdout/stderr、崩溃残留预留仍可能存在，并计入容量。本轮修复不会批量删除它们。
授权人员须先确认没有活跃任务、核对 UUID 目录及容器收据和所有权，保存仍需复核的审计信息，再按实际保留需求逐项处理原件副本和失效预留。
不能只删除活跃任务的 reservation 来绕过配额，也不能以日志/收据中未经验证的路径对其他目录或容器执行清理。APK、政策、凭据和私有收据保持在 git 排除范围内。

## 两种不同的“覆盖”

- `coverage.status`（worker CLI 为 `completeness`）兼容保留 COMPLETE/PARTIAL；新增 `scope=DEX_ENTRIES` 明确它仅表示本轮列出与处理的 DEX 条目。COMPLETE 仍要求主 DEX 存在、没有 DEX 解析失败且不是 split APK。
- `behavior_detection=LIMITED_RULE_BASED_STATIC` 和 `behavior_limitations` 独立说明有限规则的静态识别范围。反射、动态加载、Native、加壳、第三方/混合运行时、复杂控制流与跨过程数据流、规则未覆盖行为不作穷尽承诺。
- 规则未命中不代表没有隐私行为。扫描完成不等于检测全面，更不证明实际收集、外传、安全性或合法性。
- 旧作业未含新字段时，API 补上保守默认说明；不改动结论、证据、政策原句或引用关系。
