## 4. 对现有分支的影响

- 所有基于旧 `main` 的分支，与重写后的 `main` 共用祖先会退回到 10-13 之前，直接 merge 会产生大量伪冲突。
- 对齐方法：把分支的提交重放到新的 `main` 上。若分支内容已包含旧 `main` 的全部改动，
  可以直接沿用每个提交原有的树，只改父链，这样内容不会漂移。

```bash
git fetch origin
git switch <branch>
git rebase --onto origin/main <old-main-head> <branch>
# 冲突且确认分支内容为准时，可逐个核验树是否与改写前一致
```

- 已修复的三个开放 PR：
  - #88 `codex/issue70-package-sets-remote-task`：把 24 个自有提交重放到新 `main`，树与 R11 候选 `9cb45d0` 一致，不再携带旧历史。

- 其余远端分支中，多数内容已包含在 `main` 内（patch 等价），无需处理；
