# 场景与故障注入计划

本表是待执行计划，当前所有案例均 NOT_RUN。统一前置、状态和记录规则见 [入口](README.md)；材料见 [清单](materials.md)。使用既有主流程与 API，不新增验收专用分析 pipeline。

## 统一主流程与通过条件

Android 选择并确认已安装的受控 App → 读取单 APK 或 base＋全部已安装 splits → 官方或兼容自托管的免登录 HTTPS → 任务授权与持久队列 → 专用 Runner 的真实隔离 Docker 扫描 → 自动政策或既有辅助输入 → 手机报告定位静态证据和政策原句。

每个成功组合都要检查：

- 用户确认的包名、版本、base/splits 名称、各文件及集合摘要与服务端接收一致；不上传整机应用清单。
- 手机实际访问正确 HTTPS 实例，无账号登录；授权材料按实例与任务隔离。
- 队列、租约/尝试、Runner 和隔离扫描属于同一任务与固定镜像，报告来自本次扫描。只有 API 收到请求或 job 为 SUCCEEDED 不足以证明全部链路。
- 自动政策保留抓取来源；网页辅助和手机模型 API 经 #70/#72 的既有适配/校验回到同一任务。补入前后保留来源、哈希、原句及候选审计，不自动变为已复核。
- 手机能下钻到同一输入版本的代码位置和政策原句，原文区间正确；缺证据/部分/未知保留，迟到响应不能覆盖新任务或实例。
- 脱敏记录同时覆盖客户端动作、API 观察、持久状态和 Docker inspect。不能只提交报告截图。

## 包、授权与政策负向

以下动作由代理在一次隔离测试运行内执行。A/B 表示两个独立任务作用域，I/J 表示两个独立实例；真实凭证仅在私有运行器中传入，不写入公开命令或记录。

| 案例 | 动作／注入时点 | 通过观察与必须保留的证据 |
| --- | --- | --- |
| N01 | 选择前取消、确认时取消；随后重新选包 | 无未确认上传/作业；重新选择可用；保留脱敏网络请求计数及 UI 状态 |
| N02 | 测试安装中变更版本、卸载或令所选组件不可读，再确认/读取 | 拒绝完整成功，不提交部分集合；记录安装快照、固定错误码及无新成功报告 |
| N03 | 对专用受控 splits 集合遗漏必需 split、混入错版本/包名/重复名、损坏摘要 | 客户端/服务端按真实入口拒绝；不得默默降为 base-only；逐变体记录接收与拒绝，主机不解析真实 APK |
| N04 | 包/集合超过配置限额，流式超限、慢上传与中途断流 | 有界失败/背压、无半成品发布；重试不复用残留；记录字节界限、耗时、清理后状态 |
| N05 | 用 A 的访问材料读写 B 的状态/材料/报告/取消/删除；再用缺失、损坏材料重试 | 每个端点拒绝，不泄露目标资源或改变 B；对照前后 B 状态。若成功即 FAILED，不吞掉异常 |
| N06 | 从 I 切至 J，尝试复用 I 的任务材料，保留一次旧请求迟到响应 | J 拒绝跨实例材料；旧响应不能覆写当前任务/实例；记录响应及当前选中对象 |
| N07 | 无效证书、错误主机名、TLS 降级或用户输入 HTTP 实例 | 正常信任校验拒绝，不关闭校验、不以安装测试 CA 代表公有信任；保存证书公开指纹及错误类别 |
| N08 | 请求 API 管理探针、DB/broker/Runner/daemon 管理入口与未公开端口 | 从实际客户端网络不能取得管理资源；以可达性和真实监听/隔离配置佐证，不能仅看 YAML |
| N09 | 政策地址指向回环/私网/元数据、重定向到禁止目标、超大或慢响应 | 来源安全与资源限制生效；无内部数据返回、无无限等待；保留脱敏目的地类别、拒绝及出站观察 |
| N10 | 在任务已有可用政策时注入抓取失败；再补入畸形原句区间/引用/冲突候选 | 旧材料与审计保留，错误显式呈现；无效引用拒绝；不自动重新抽取或升级复核/完整性状态 |
| N11 | 手机配置一次性测试模型凭据并调用辅助 API，观察客户端出站和分析服务入口 | 手机仅向预定模型端点发送该凭据，分析服务入口无该凭据；记录实际覆盖的传输面。无解密可见性则保留未验证，抓包只留私有区 |
| N12 | 手机离线、后台/系统回收后恢复；断网时取消或由用户显式重试 | 显示真实状态；后台恢复只重新读取原任务，用户显式重试必须创建新任务 ID 并保留旧报告；不伪造成功或因恢复重复提交，记录请求与持久状态对应关系 |

## 运行时、删除和运维故障

前置是 #80/#81 提供角色命令、认证方式、专用 Linux/扫描主机、恢复步骤与可销毁测试卷。先用正常主流程建立基线任务；每次只注入一个因素，再恢复并观察结果。角色名和命令必须来自上游实际交接，不猜造 Celery/Runner CLI 或绕过生产门禁。

| 案例 | 注入／恢复步骤 | 外部通过条件与证据 |
| --- | --- | --- |
| F01 | 持久接收后停止 API，再按已交接命令启动 | 客户端恢复读取同一任务；已确认接收不丢失、未确认接收可幂等重试；保留接收点与重启前后事件 |
| F02 | 待投递与已投递阶段分别停 broker / outbox publisher，再恢复 | 已持久任务最终可投递；有限重试/可见错误，无丢单；记录 outbox 和 broker/作业关联，不公开消息凭证 |
| F03 | worker / Runner 领取后分别中断，在租约到期前后恢复 | 正确回收/重试或最终失败；旧 fencing token 不得提交；无双重有效终态。每个组件单独记录 |
| F04 | 对同一投递重复交付；让旧尝试在新尝试完成后回报 | 有效结果仅一次，旧结果拒绝；报告索引、事件和材料一致，不因多条消息复制有效结果 |
| F05 | 排队、上传/扫描中、提交前各执行取消 | 状态与实际停机/清理符合交接契约，旧结果不得复活任务；记录取消确认点与资源回收 |
| F06 | 与 F05 相同时点删除任务，再送达迟到结果/旧访问请求 | 已删除材料/索引不可再访问且不重建；旧结果拒绝，删除事实持久；记录各存储层脱敏核对 |
| F07 | 专用扫描容器超时/崩溃，测试主机在运行中重启，随后重建角色 | 有限失败/恢复，不留孤儿任务/容器/临时材料；实际 inspect 确认隔离、当前任务只读输入和无秘密 |
| F08 | 初始并发 1 下提交第二个任务，分别耗尽准入、队列/磁盘预算 | 有界排队或明确背压，不无限增长；记录硬件、限额、耗时、峰值内存/磁盘与拒绝响应，不能补零代替未测 |
| F09 | 按 #81 运维步骤备份专用 DB/私有材料；删除一个任务后恢复较早备份，再重放删除记录 | 备份点、材料与索引一致，已删除对象不可复活；保存恢复点/删除水位及旧访问材料拒绝证据 |
| F10 | 在可回滚测试副本执行已交接升级/回滚、内部凭据轮换及磁盘满恢复 | 版本/迁移兼容或明确阻止危险回滚；新旧凭据按策略生效/失效；无永久假就绪，数据可核对 |

F01–F10 不在他人现有测试栈执行，不重放真实用户任务，不把基础 PostgreSQL/Redis 哨兵重建当成应用一致恢复。记录实际注入命令的脱敏版本、时间线、预期、观察和清理结果。
