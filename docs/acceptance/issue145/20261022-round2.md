# Issue #145 · 第二轮：Android 竖屏外壳的状态、焦点与无障碍

来源任务：[#145](https://github.com/MrEcho114/PrivacyTrace/issues/145)，父票 [#141](https://github.com/MrEcho114/PrivacyTrace/issues/141)。
第一轮交付：[PR #158](https://github.com/MrEcho114/PrivacyTrace/pull/158)，head `5f12bcf`，桌面 14 组状态/焦点检查通过。
第二轮不再重复桌面改造，而是把第一轮的语义接到 #144 的 Android 竖屏外壳上，并在 `codex/frontend-round2` 整合树复验。设计合同见 `docs/design/frontend-round2-android-pioneer.md` §5。

## 本轮实际改动

- 顶栏：`header` + 唯一 `h1#page-title`（`tabindex=-1`）；返回/设置按钮有可访问名称，设置按钮声明 `aria-haspopup="dialog"`；程序化聚焦标题不绘制控件式焦点环（`h1:focus { outline: none }`），交互控件仍保留全局 3px 焦点环。
- 步骤条：`nav aria-label="创建流程"`，唯一 `aria-current="step"`，未来步骤 `disabled`；桌面与移动共用同一语义。
- 主内容：`main#workspace-content` + skip link；步骤切换后焦点落到标题，滚动位置按步骤恢复，轮询不抢焦点/不重置滚动。
- 固定操作栏：`footer[role="group"][aria-label="当前步骤操作"]`；主/次按钮来自可见文字，busy/disabled 语义沿用 `UiButton`，不嵌入 live region。
- 忙碌提示：拆成 `span[role=status]` 文本 + 独立停止按钮（D 第一轮规则在移动外壳继续成立）；失败/取消仍为 `role=alert`，只在终态出现。
- 证据 sheet（复用 A 的 `UiSheet`/Reka Dialog）：原生 `dialog`、`aria-modal="true"`、`aria-labelledby` 指向问题标题、`aria-describedby` 指向范围说明；焦点进入 sheet，关闭按钮 48×48 有 `关闭` 名称，Esc / 硬件返回 / scrim 点击都能关闭，关闭后焦点回到触发行并恢复报告滚动位置；背景 `aria-hidden` 由 Reka 提供。
- 设置：继续用 Reka `UiSheet` 的 `detail` 全屏变体，标题/描述/关闭名称/焦点陷阱/返回触发器保持第一轮结论。
- 200% 字体：步骤条、固定操作栏和表单都不产生页面级横向滚动；操作栏高度实测变量保证内容不被遮住。
- 候选/报告：候选列表命名分组、来源切换 segmented control 的 roving tabindex、报告问题行按钮化、分页/证据入口保持可键盘操作；来源身份不再在阅读面板重复（B 的宽屏层级守卫）。
