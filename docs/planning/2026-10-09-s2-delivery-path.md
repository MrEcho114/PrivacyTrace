## 1. 已确认目标与不做项

以可验证的竞赛作品为目标：证据可追溯、缺证据时谨慎降级为主，公平评测支撑，界面做到演示顺畅。人工准备并核对政策候选，明确披露人工输入，不宣称自动政策理解或自动抽取准确率。

保底 1 个真实 App 案例 + 6 个自建受控场景，余力扩到 8 个。真实 GKD 案例的现有版本绑定记录可作为案例起点，不声称本轮重新扫描、政策已核验或证明全局行为。

本期不新增网页 APK 上传、多人公网服务、动态分析、SDK 扩展或 LLM 自动抽取主线；未来若确有赛道要求须重新确认取舍。演示保持本地 CLI 分析 + 浏览器报告，清楚区分实时扫描与离线回放。APK、完整政策、私有路径与凭证不混入公开提交；离线材料的分发另核对授权，不自动 Release。

## 3. 三个技术模块

| 模块 | 责任安排 | 首次交付 |
|---|---|---|
| 受控输入、公平评测、最终整合 | 用户本人 | 受控输入边界、运行前冻结真值、三方案 runner、两个场景结果 |
| APK 源码与可重复构建 | 技术队友之一，具体人待认领 | 锁定构建环境、源码、构建脚本、产物与输入哈希 |
| 浏览器异常与离线交付 | 另一技术队友，具体人待认领 | 真实浏览器异常记录、回放标识、干净环境运行指引 |

用户约 8H/日；另外两位工时尚未确认，不按全队 24H/日推算。辅助成员可整理材料/录屏，但不承担未经验证的技术裁定。账号类型不替代能力核实；各模块接口对齐后并行，不让多人同时大改核心文件。

## 5. 受控入口与评测边界

受控入口必须明确标识，与真实 App 分开。已核对的自建样本适用范围与政策事实可作为已知输入；原有未知真实信息不补造，不修改历史 capture/report。扫描及规则引擎复用，隔离与原有校验不全局放宽。参见 [ADR 0002](../adr/0002-controlled-benchmark-boundary.md)。

真值在运行前从场景定义与政策原文独立冻结；被测方案不读取预期答案，运行之后才比较。人工候选是输入，预期判定是标签，不能混为同一文件被算法直接读取或按系统输出改答案。

三组方案：权限 + 关键词、同一 API 证据/完整描述符 + 扁平匹配、本方案规则对照。各组获得相同材料；写明各基线使用哪些信息，不故意制造弱描述符基线。人工输入的工作量要单列，不把本轮包装成自动政策抽取实验。

建议评测输出为逐场景预期/实际、映射与定位核对、误判/弃判、覆盖率、失败留痕、耗时与必要的 P/R/F1。计数单位和可测目标开跑前固化，零分母 N/A；失败/partial/弃判不悄悄删除，小样本不作统计代表性或商业 App 全局召回宣称，不预设本方案优于基线。

## 6. 检查点与验收

- **10/10–12**：构建工程 + C02/C06 最小闭环，贯穿实际 APK 扫描、受控输入、三方案 runner 和浏览器；输入与预期结果不串线。
- **10/13–15**：扩到六场景，记录真实比较结果与误差；浏览器覆盖异常数据/长文本/来源切换/取消与失败提示，未测项不冒充通过。
- **10/16**：独立或干净环境离线运行验证，核对回放来源、报告留存和材料技术事实。没有实际断网运行就不称离线验收完成。
- **10/17**：冻结代码，之后只修交付阻塞问题、整理材料；不自动合并、发布、部署或正式提交比赛。

保底完成以可重复构建、实际扫描/HTTP/浏览器证据、六场景 runner 真实结果、输入版本/哈希、权威项目检查及干净环境回放为依据。工程测试、受控评测、真实样本记录分别统计，CI 绑定交付 SHA。

**10/12 止损**：双场景闭环未通就取消 C07/C08、停止非必要修改；若多状态评测仍有实质阻塞，重新与用户确认降低实验目标。不能偷偷减少六场景保底、伪造成功或放松真实输入限制。
