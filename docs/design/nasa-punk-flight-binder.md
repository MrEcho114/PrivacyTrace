# NASA-punk 第二方向：Flight Binder / 任务装订册

> 状态：设计提案 + 静态视觉原型，**不是产品验收，也不是对 Codex 现有 #142 规范的替换**。
> 日期：2026-10-22。范围：视觉语言、token、组件外观、报告/候选代表页、实现边界。
> 基线：`codex/frontend-round2` `9ec644e`（含 A–E 与移动阅读增量）。本分支只新增设计文档、独立 HTML 原型和截图，不改 `apps/web`、锁文件、API、flow 或现有测试。
> 协作：Codex 已在 [#142](https://github.com/MrEcho114/PrivacyTrace/issues/142) 登记一版 NASA-punk 规范；本方向作为**并列第二方案**供选择/合并，不改写其评论、不认领其执行记录、不修改其工作树。

## 1. 设计命题

**“一本摊在白色工作台上的任务装订册，而不是一块发光的飞船仪表盘。”**

PrivacyTrace 的核心不是“炫技的太空 HUD”，而是把静态证据、政策原句、任务状态放到同一张可核对的桌面上。NASA-punk 在这里应表达 **1970 年代政府技术文档的秩序感 + 被维护过的飞行硬件**，不是科幻游戏。

三条只属于本方向的判断：

1. **装订册，不是面板堆**：内容由纸面、装订索引、裁切标签和文档控制条组织；面板只是纸张分区，不是一叠相同的圆角卡片。
2. **红色是一枚实体按键**：全页只有“现在要做的那个动作”是红底白字；当前步骤用红色小方块标记，其余状态用文字、线型、灰度表达。
3. **痕迹只在边缘**：铆钉只出现在外框四角，划痕/贴纸/铅笔提醒只占空白边缘；文字、按钮、焦点环永远干净。

与 Codex 方向的差异不是配色，而是**组织隐喻**：Codex 的“设备面板（device panel）”更强调整体硬件外壳；本方向把产品理解为**任务文件/检查单**，因此采用不对称索引栏、裁切标签、文档控制条和双页展开，降低“每个页面都是一张卡片”的模板感。

## 3. Token：先定义“纸、墨、线、身份、红色”

所有变量以 `--np-*` 命名，作为 **Pioneer 之上的视觉覆盖层**；不改写现有 `--canvas/--surface/--navy` 的语义。实现时应在一个受限 scope（如 `[data-theme="nasa-punk"]`）内消费，先保证可回退。

### 3.1 颜色

| Token | 值 | 角色 | 规则 |
| --- | --- | --- | --- |
| `--np-paper` | `#FFFFFF` | 画布/正文/侧栏/内容面板 | 页面主色；不铺米色、不做大面积深色 |
| `--np-topbar` | `#ECE5D6` | 仅顶栏 | 唯一允许的米白面；不铺到卡片/正文 |
| `--np-ink` | `#252A2E` | 标题/正文 | 对比 14.49:1（白底） |
| `--np-rule` | `#4C5A68` | 1px 分隔线/刻度/次级标签 | 对比 7.07:1；不拿它当正文大段颜色 |
| `--np-muted` | `#6B6F72` | 辅助说明 | 对比 5.07:1；不小于 12px |
| `--np-ribbon-1` | `#4C5A68` | 身份条第 1 段 | 只做身份装饰，不映射状态 |
| `--np-ribbon-2` | `#7A7F4E` | 身份条第 2 段 | 不用于文字（白底 4.22:1） |
| `--np-ribbon-3` | `#D2A85E` | 身份条第 3 段 | 不用于文字；深底上 6.56:1 |
| `--np-ribbon-4` | `#A8432F` | 身份条第 4 段 | 只做身份/警示边，不替代错误语义 |
| `--np-red` | `#D63A2C` | 唯一鲜艳强调 | 只用于主 CTA、当前步骤标记、当前选中证据标记 |
| `--np-red-press` | `#B92E24` | 红色按压 | 只作按压/激活，不新增第二红 |
| `--np-on-red` | `#FFFFFF` | 红底文字 | 对比 4.67:1，满足 AA 正文；仍只放大号/粗体按钮文字 |
| `--np-caution` | `#17181A` | 黑白警示条纹的黑 | 只做 6px 功能条 |
| `--np-line-soft` | `rgba(76,90,104,.28)` | 面板内分隔 | 不用于可点击边界 |
| `--np-stamp` | `#7A7F4E` | 印章/贴纸 | 低饱和、只在外围；不承载唯一信息 |

**红色预算：** 每屏最多 1 个红底主按钮 + 1 个当前步骤红标记；报告页无主按钮时，红只落在“当前证据行”的 2px 标记。红色不用于普通链接、所有图标、所有状态标签。
**状态：** 不复用四色条表达 UNKNOWN/PARTIAL/UNREVIEWED。状态标签使用中文文字 + 细边框/虚线/双线 + 可读的图形符号；语义色只允许低饱和小面积，不能盖过红色 CTA。

### 3.2 字体

| 角色 | 字体栈 | 用法 |
| --- | --- | --- |
| 中文标题/正文 | `Noto Sans SC`, `Microsoft YaHei`, `system-ui` | 标题 650–700；正文 400/500；不再用 Noto Serif SC 做大标题 |
| 拉丁宽标题 | `Helvetica Neue`, `Helvetica`, `Arial`, `Noto Sans SC` | 大写、`letter-spacing:.08em`、700；无 Univers 文件时不伪造宽度 |
| 功能标签/编号/数据 | `ui-monospace`, `Consolas`, `"Courier New"` | 大写、10–11px、`letter-spacing:.12em`、`tabular-nums` |
| 手写提醒（可选） | `Segoe Script`, `Bradley Hand`, `cursive` | 只允许英文短语，放在空白边缘；`aria-hidden`，中文信息不依赖它 |

字号（桌面 / 移动）：

| 层级 | 桌面 | 移动 |
| --- | --- | --- |
| 文档标题/品牌 | 28–32px / 1.05 | 20–22px / 1.1 |
| 区块标题 | 18–20px / 1.2 | 16px / 1.3 |
| 正文 | 15px / 1.6 | 15px / 1.65 |
| 功能标签 | 11px mono / .12em | 10.5px mono / .12em |
| 数据 | 13px mono / tabular | 12px mono / tabular |

不使用外部字体 CDN；中文由现有本地 Noto Sans SC 承载。

### 3.3 几何、网格、表面

- 8px 基线，4px 半格；面板间距 16/24；桌面 12 列，移动 4 列。
- 面板：`border:1px solid var(--np-rule)`，圆角 **2px**（不是 12px 卡片）；不用柔和投影，最多 `2px 2px 0` 硬偏移，且仅用于“凸起”的少量关键块。
- 外框：1px 线 + 四角 6px 铆钉；**内部面板不加铆钉**。
- 分隔：1px `--np-line-soft`；重要分区间用 2px `--np-rule`；不使用阴影分隔。
- 裁切标签：步骤/索引使用左侧 2px 竖条 + 右上角 6px 缺角（`clip-path` 可选）；标签本身是导航，不是装饰。
- 纸面纹理：**不铺满**；只在 `.np-frame` 外缘用 1px 半透明划痕，正文层保持纯白。
- 黑色警示条纹：6px 高，`repeating-linear-gradient(135deg, #17181A 0 6px, #fff 6px 12px)`；只用于“静态线索不证明实际采集”边界与危险确认区。
- 磨损：外框 4 角少量 1px 划痕、1 枚低饱和印章/贴纸、1 条红铅笔英文提醒；不覆盖文字/控件/焦点环，全部 `aria-hidden`/pointer-events:none。
- 方向标记：桌面外框左边缘可放一条竖排 `THIS SIDE UP ↑` 的制版/方向标记（8px mono、低对比、`aria-hidden`）；它是印刷/装订语义，不进入内容区，不伪造 `STOW 84S` 式任务编号。

## 4. 版式

### 4.1 桌面（≥1200px）：索引栏 + 双页展开

```text
┌──────────────────────────────────────────────────────────────┐
│ PRIVACYTRACE  证据对照工作台        DESIGN STUDY 02   ⚙     │ 64
│ ████ ████ ████ ████  (四色身份条 6px)                        │
├───────────────┬──────────────────────────────────────────────┤
│ 01 导入材料   │ REPORT / 04        STATIC ANALYSIS  REAL_SCAN│
│ 02 检查候选   │ ┌──────────────────────┬───────────────────┐ │
│ 03 分析进度   │ │ 应用身份 · 版本       │ MISSION LOG       │ │
│ 04 对照报告 ◀ │ │ REAL_SCAN / REPLAY   │ 2 数据类型        │ │
│               │ │ 数量行 · 边界声明     │ 1 政策来源        │ │
│ MISSION INDEX │ ├──────────────────────┤ 3 可查看证据      │ │
│ 01 / 02 / 03  │ │ 结论 + 证据入口       │ 来源/时间 ▾       │ │
│ 裁切标签       │ │ E-01 原句/定位        │ 静态边界条        │ │
│               │ └──────────────────────┴───────────────────┘ │
└───────────────┴──────────────────────────────────────────────┘
```

- 左栏 220px：竖向裁切索引，当前项左侧 3px 红条 + 墨色文字；不再用四步横条重复。
- 右栏是 `REPORT` 纸张：左页 7 列（结论/证据），右页 5 列（任务日志/技术细节）；中间 1px 装订缝。
- 报告第一屏必须同时出现：应用身份、REAL_SCAN/REPLAY、静态边界、至少一条结论及证据入口。
- 技术信息（包名、哈希、完整时间、材料 ID）进入右页“MISSION LOG”或 `<details>`，不抢占首屏。
- 不用大面积米色；顶栏米白只到 64px 高，身份条 6px。

```text
│ ███ ███ ███ ███ (身份条 4px) │

├──────────────────────────────┤
│ REPORT / 04      REAL_SCAN   │
│ 手机端验收示例               │
│ 版本 1.0.7   [REAL_SCAN][REPLAY] │

│ 数据类型 2  政策来源 1  证据 3 │
├──────────────────────────────┤
│ 位置信息  具体类型已声明·待复核│
│ 查看 2 条证据 →               │
├──────────────────────────────┤
│ 设备标识  未找到声明·待复核   │

└──────────────────────────────┘
```

- 文档控制条 22–26px + 顶栏 56px（含 4px 身份条）+ 安全区；步骤条 48px 单行，当前项用红色小方块，标签不换行到第二行。
- 不显示固定底部操作栏（报告页无业务动作）；候选/进度页才显示 64px 操作栏，主键红底、次键墨线。
- 材料条用 `MANIFEST / REV` 的装订标签，不把“详情/更换”各占一行。
- 320px 时索引标签可水平滚动，但主内容不得横向滚动；200% 字号时标题换行不截断，操作栏高度自适应。

### 4.3 导入 / 候选 / 进度

- **导入**：整页是一张 `MATERIAL INTAKE` 检查单；左侧字段（应用/包集合/来源），右侧“当前分析服务”与保留策略；主按钮“选择应用并上传”红底。空态不是空白卡片，而是一张带编号字段的空白表格。
- **候选**：`SOURCE 01`（政策原文）与 `CANDIDATE 01`（候选声明）用双页/移动 Tabs；候选行是 ledger 行，左侧 2px 灰线，选中时 2px 红线；主按钮“保存候选并开始分析”。
- **进度**：`RUN LOG` 时间线；阶段用 mono 编号和文字，当前阶段红色小方块；停止/取消是次级描边动作，不做红色大按钮（避免与“继续”竞争）。错误用实线框 + 文字，不用红色铺底。

| --- | --- | --- |
| `UiButton` primary | 红底白字、2px 圆角、700；按压 `--np-red-press` | 不把所有主操作变红；不发光 |

## 6. 动效与可达性

- 动效只表达状态：按压 120ms，面板/详情展开 160ms opacity/height，步骤切换 160ms；不使用扫描线、发光、粒子、持续动画。
- `prefers-reduced-motion: reduce` 下全部即时；`transition` 只列具体属性，不用 `all`。
- 焦点环：2px `--np-ink` + 2px 白 offset；**不用红色焦点环**，保持红色唯一性。所有焦点可见。
- 触控：48×48；输入 ≥16px；底部操作栏 `env(safe-area-inset-bottom)`；不使用纯 hover 传达信息。
- 对比：红底白字 4.67:1；红字只用于白底大号（≥18.66px bold）或非文本标记；`#7A7F4E` 只做色条，不做文字；`#ECE5D6` 上不用小红字。
- 语义：英文大写标签是辅助扫描，中文可访问名称必须完整；装饰标签/铆钉/划痕/铅笔字 `aria-hidden`；不生成虚假任务号/进度/认证。
- 证据边界：红/四色/条纹都不表示“安全/违规/已采集”；UNKNOWN/PARTIAL/UNREVIEWED 继续用文字和原始状态。

## 7. 与 Codex 方向的关系

| 维度 | Codex #142 规范 | 本方向 |
| --- | --- | --- |
| 隐喻 | 设备面板 / 航天硬件外壳 | 任务装订册 / 飞行检查单 |
| 结构 | 顶栏 + 横向步骤 + 面板 | 文档控制条 + 竖向裁切索引 + 双页展开 |
| 视觉重心 | 面板接缝、铆钉、身份条 | 纸张/装订缝、索引标签、双页阅读顺序 |
| 身份 | 四色条或任务徽章 | 只做四色条；不加徽章 |
| 红色 | 主 CTA + 重要标记 | 主 CTA + 当前步骤/当前证据，预算更窄 |
| 纹理 | 面板金属感/磨损 | 只在装订册外框，正文纯白 |
| 复用 | 现有 token/组件 | 同样复用；额外定义 `--np-*` 覆盖层，可回退 |

两者共享用户硬约束（白底、米白顶栏、四色、单红、无霓虹/全息/大渐变、功能标签、轻磨损）。**不合并两份评论**；由 #141 整合 owner 决定采纳哪套，或只合并 token/版式部分。本方向不修改 #142 的规范评论、不修改 Codex 工作树、不 push 到 #160。

## 8. 自评：哪里可能出错

- **过度装饰**：铆钉/划痕/印章很容易变成“主题皮肤”。约束：铆钉只在最外框四角，划痕只在空白边缘，正文/控件零纹理。
- **白色太空**：白底 + 细线可能显得像普通后台。本方向的辨识度必须来自**装订索引 + 双页缝 + 文档控制条**，不是再加纹理。
- **英文标签噪音**：全大写 mono 标签会挤压中文。约束：标签只做 10–11px 次级信息，中文标题/操作永远更大；英文不承载唯一语义。
- **红色滥用**：红色一旦用于状态/链接就会失去“唯一按键”意义。约束：每屏红预算 1+1，状态用文字/线型。
- **字体不可得**：Univers Extended 无授权文件；不伪造 `font-stretch`，用 Helvetica/Arial + 字距表达，中文由 Noto Sans SC 承载。
- **和 Codex 撞车**：本方向只交付独立文档/原型/token 提案；不在共享 `theme.css`/组件上先斩后奏。真正落地需在 #160 上按 owner 串行整合，并重跑 A–E。
- **证据误读**：四色条/红色/警示条可能被误读为风险等级。文档和 UI 都明确它们是身份/操作/边界，不是结论。

## 9. 落地顺序与验收

1. **先做代表页**：报告（桌面双页 + 移动单页）→ 候选 → 导入/进度。先验证阅读顺序和红色预算，再扩展。
2. **token 层**：新增 `--np-*` 覆盖层 + `[data-theme="nasa-punk"]` scope；保留 Pioneer 回退。不改现有语义 token 名。
3. **组件层**：面板/印章/索引/警示条/按钮/字段/标签/sheet；不新增运行时依赖。
4. **页面层**：只改外观和标签，不碰 flow/API/证据状态；共享文件由单一 owner 串行写。
5. **验收**：1440/390 代表页实渲染截图；320/768/200%/键盘/reduced-motion；对比度；无横向溢出；不新增装饰性 Tab 停靠点；A–E 脚本 + reading 全部复跑；真实 Android/读屏仍 `NOT_RUN`，不以原型截图替代。
