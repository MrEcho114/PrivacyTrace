### 为什么做
确保提交的作品能在断网、无外部大模型密钥的评审环境下顺利运行，并能通过离线回放模式完整查看预冻结的分析报告。

### 做什么（输入与输出）
- **输入**：冻结的代码、依赖锁文件、预先生成的分析报告快照与测试样本。
- **输出**：
  1. 构建离线交付包，包含前端构建静态文件、后端源码、锁定版本的依赖清单及预置数据；
  2. 编写单机运行操作指引，清晰记录系统启动步骤与前置依赖要求；
  3. 提供离线回放功能：在无大模型 API 密钥且无外网连接时，可直接查阅预冻结的报告，明确标注“离线回放数据”及生成时间；
  4. 实测验证依赖离线安装的可行性，不夸大宣称“任何全新电脑一键秒级运行”；
  5. 清理包内文件：彻底移除私有凭证、临时调试文件与未授权的商业二进制文件。

### 完成标准（验收证据）
- 按照说明文档在独立或干净环境中能正常启动服务并访问离线回放报告；
- 交付包内无任何硬编码密钥或未授权数据，文件清单与 SHA-256 记录完整；
- 最终的 pytest、Ruff 检查、类型检查与前端 build 均有通过记录，结果记录在案。

### 怎么检查（验证计划）
- 在独立环境或虚拟机中解压该包，断开网络执行启动命令并验证页面功能；
- 运行敏感词与私钥扫描脚本，检查包内是否存在 `.env` 或凭据文件；
- 核对包内文件清单与哈希值。

### 这次不做
- 不向公开代码库发布未授权的商业依赖或正式 Release；
- 绝不通过虚假录屏将离线回放伪装成是实时联网分析。
