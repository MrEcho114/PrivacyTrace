# 桌面 Pioneer 契约延后退役，触发条件是桌面入口正式下线

2026-10-23，前端范围已收窄到仅移动端 App，移动侧改用 Claude 基线与 `--ui-*`/`--mt-*` 契约；桌面 Web 工作台视觉冻结，但 `WorkflowApp` 仍是浏览器默认入口，`pioneer-design.json` 与 `verify-round2-primitives.cjs` 继续保护这套仍在仓库、仍可运行的桌面表面。

决定：**现在不退役**。两份契约保留到桌面 Web 入口被产品正式下线或移出受支持范围；在此之前不删除、不弱化、不静默跳过。桌面视觉冻结期的维护成本（双色板、双几何）接受，换取“冻结”有可执行断言，而不是口头约定。

## 退役触发条件

同时满足才启动退役：

1. 用户/产品明确桌面 Web 工作台不再作为受支持入口（或代码被删除、归档）；
2. 没有在途桌面功能改动，桌面验收基线已归档；
3. 移动契约 `scripts/fixtures/mobile-design.json` + `assertMobileDesign` 已覆盖移动全部界面与共享组件，且不依赖桌面 fixture；
4. 退役改动在同一个变更里完成：删除 `scripts/fixtures/pioneer-design.json`、`scripts/verify-round2-primitives.cjs`、`verify-frontend-flow.cjs` 中的桌面专属断言与桌面截图，更新 `AGENTS.md`、`docs/agents/frontend-delivery.md`、移动规范 §11/§12 与本 ADR 状态；移动契约与移动验收不得删除。

## 复审点

- 下一次前端设计/交付轮次开始时复审；若届时仍无桌面下线决定，保持现状并把复审点顺延。
- 最早复审日：2026-11-06。若桌面代码连续两个发布周期无人改动、且移动是唯一发布入口，可作为启动退役的信号，但仍需用户确认第 1 条。
- 负责人：当前交付主代理；决定权：用户。任何提前删除都视为违反本 ADR，需先改本 ADR。

## 后果

- 正面：桌面冻结仍有机器可读断言；移动重构不会误伤桌面；退役时有明确清单。
- 负面：`--ui-*` 别名与 Pioneer 旧变量需要并存一段时间，新增共享组件要同时满足两套值；这是冻结期的已知成本。
- 过渡约束：共享组件只消费 `--ui-*`，移动壳由 `body.is-mobile-app` 映射到 `--mt-*`；旧变量重映射在别名消费完成后删除，不把“过渡态”当成长期架构。
