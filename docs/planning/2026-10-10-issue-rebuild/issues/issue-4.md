## Problem Statement

S1已合并，原S2工单缺少独立受控入口/真值和最小贯通检查点。团队需要在10/17冻结前证明静态证据可追溯与谨慎降级，并提供公平比较。

## Solution

先以 {{PT-910}} 打通C02/C06从源码构建→隔离扫描→受控输入→三方案运行→HTTP/浏览器，再由#16扩到六场景、#25形成正式结果；#17并行验证界面异常。保底1个既有真实GKD案例+6个自建场景，余力到8。

## User Stories

1. 阅读者能看到静态调用、政策原句及对应边界。
2. 评测者能从源码重复构建，在运行前冻结独立真值。
3. 三方案使用同一材料，失败/partial/弃判不删除。
4. 演示者能区分真实样本、受控场景、示例与离线回放。
5. 团队能按工单阻塞顺序独立领取可演示任务。

## Implementation Decisions

遵守本地CLI+浏览器以及受控/真实信任边界两项ADR；复用S1扫描/规则/报告。人工候选是输入，预期答案是标签，分文件且算法不可读标签；只对实际核对的自建适用范围/政策事实赋已知值，不修改真实未知状态。

六场景为C01权限无调用→证据不足、C02明确类型→精确对应、C03上位类别→类别对应、C04完整适用政策缺声明→未声明、C05否定与静态调用并存→模糊披露、C06信息不全→证据不足。覆盖5类状态；多来源冲突/Multidex为扩展，不声称六状态全覆盖。

用户负责受控输入、公平评测与整合；队友分别负责源码构建、浏览器/离线，具体人/工时待核实。

## Testing Decisions

最高层验收使用实际源码产物经CLI→HTTP→浏览器；三方案同材料/正确描述符，运行后才读取冻结标签比较。状态、定位、全样本覆盖与失败/弃判分列，P/R/F1先定义目标/计数，零分母N/A。权威工程检查绑定交付SHA，不用回归数顶替受控评测。
